# Карта правок: где что менять

Этот файл отвечает на один вопрос: **«мне надо поменять вот это — куда лезть?»**

Для каждой правки написано: что открыть, что найти, что заменить и какую
команду запустить после. Программистом быть не нужно.

---

## Прежде чем что-то менять

**Сделайте копию.** Одна команда, одна секунда:

```
cd ~/Desktop/"tasin dunya" && node scripts/backup.js
```

Если после правки что-то поедет — возьмёте файлы из папки `backups/` и
положите обратно. Ничего страшного не случится.

**Про номера строк ниже.** Они верны на сегодня, но после правок текст
сдвигается. Поэтому у каждой правки написано не только «строка 24», но и
**что искать** — ищите по тексту (в любом редакторе это `Ctrl+F`, на Mac `Cmd+F`),
так надёжнее.

## 1. Поменять телефон

**Файл:** `data/site.json`, около строки **24**
**Искать:** `"phones"`

Найдёте такое:

```json
"phones": [
  { "display": "ЗАПОЛНИТЬ: телефон", "tel": "ЗАПОЛНИТЬ" },
  { "display": "ЗАПОЛНИТЬ: второй телефон", "tel": "ЗАПОЛНИТЬ" }
]
```

Замените на свои номера:

```json
"phones": [
  { "display": "+993 12 34-56-78", "tel": "+99312345678" },
  { "display": "+993 65 12-34-56", "tel": "+99365123456" }
]
```

- `display` — как показывать людям. Пробелы и дефисы можно.
- `tel` — тот же номер **без пробелов, скобок и дефисов**, начиная с `+993`.
  По нему работает звонок с телефона.

**Первый в списке — главный**, он показывается крупно на странице контактов.
Если второй телефон не нужен — удалите его строку целиком вместе с запятой
на строке выше.

**После правки:**
```
node scripts/sync-layout.js
```
Телефон обновится сразу на всех 33 страницах: в подвале, в блоках призыва,
на странице контактов и в разметке для поисковиков.

## 2. Поменять почту, адрес, часы работы, мессенджеры

Всё там же — `data/site.json`. Найдите нужную строку:

| Что менять | Искать | Строка |
|---|---|---|
| Почта | `"email"` | ~21 |
| Домен сайта | `"domain"` | ~18 |
| Номер лицензии | `"license"` | ~19 |
| Адрес офиса | `"address"` | ~30 |
| Часы работы | `"hours"` | ~53 |
| Мессенджеры | `"messengers"` | ~85 |

### Про адрес

Адрес пишется **отдельно на каждом языке** — название улицы по-русски и
по-туркменски выглядит по-разному:

```json
"address": {
  "mapUrl": "ссылка на карту",
  "tk": { "city": "Aşgabat", "street": "...", "office": "...", "landmark": "..." },
  "ru": { "city": "Ашхабад",  "street": "...", "office": "...", "landmark": "..." },
  "en": { "city": "Ashgabat", "street": "...", "office": "...", "landmark": "..." }
}
```

- `street` — улица и дом,
- `office` — этаж и номер офиса,
- `landmark` — ориентир, по которому вас найдут («рядом с ТЦ Беркарар»),
- `mapUrl` — ссылка на точку на карте, одна на все языки.

### Про часы работы

Часы записаны **дважды**, и это не ошибка:

1. `"hours"` (~строка 53) — то, что видит человек, на трёх языках.
2. `"openingHoursSpec"` (~строка 72) — то же самое для поисковиков, в машинном виде.

**Если меняете часы — поменяйте в обоих местах.** Проверка это отслеживает:
если время разойдётся, `node scripts/preflight.js` об этом скажет.

### Про мессенджеры

```json
{
  "label": "IMO",
  "value": "номер, который увидит посетитель",
  "url": "",
  "formUrl": "",
  "note": { "tk": "...", "ru": "...", "en": "..." }
}
```

- `url` — ссылка, которая откроется по клику. **У IMO такой ссылки нет** —
  оставьте пустой, тогда просто покажется номер, его можно скопировать.
- `formUrl` — ссылка для кнопки в форме заявки, в ней `{text}` заменится
  на текст заявки. Если пусто — кнопка скопирует текст в буфер обмена.
- Ненужный мессенджер удалите целиком — блок исчезнет со страницы сам.
- **Порядок в списке = порядок на странице.** IMO стоит первым намеренно.

**После любой правки в `data/site.json`:**
```
node scripts/sync-layout.js
```

## 3. Вписать цену услуги

Цены **не** в `site.json` — они на самих страницах услуг, потому что у каждой
услуги своя.

**Файлы:** шесть страниц в папке `wizalar/`, плюс их переводы в `ru/wizalar/`
и `en/wizalar/`. Всего 18 файлов.

**Искать:** `ЗАПОЛНИТЬ: цены` (например, `wizalar/is-wizasy.html`, строка ~414)

Над блоком стоит подсказка, а сам блок обведён **пунктирной медной рамкой** —
на странице его невозможно не заметить.

Внутри найдёте две строки с прочерком `&mdash;`:

```html
<li class="pricing__row">
  <span class="pricing__label">Hyzmatymyzyň bahasy</span>
  <span class="pricing__value pricing__value--todo">&mdash;</span>
</li>
```

Замените `&mdash;` на свою цену, например `250 manatdan`. Если цену называете
только на консультации — напишите `Maslahatda aýdýarys`
(по-русски `Называем на консультации`, по-английски `We quote at the consultation`).

**Когда заполните** — уберите слово `pricing--todo` из строки

```html
<div class="pricing pricing--todo">
```

чтобы получилось `<div class="pricing">`. Пунктирная рамка станет обычной.

**Остальные строки блока менять не надо** — там честные формулировки
про консульский сбор и сроки, а не цифры.

⚠️ **Правьте все три языка.** Русская версия той же страницы лежит в
`ru/wizalar/`, английская — в `en/wizalar/`, имена файлов одинаковые.

**После правки:**
```
node scripts/preflight.js
```
Проверка покажет, не забыли ли где-нибудь прочерк.

## 5. Добавить или убрать страну в списке направлений

**Файл:** `data/countries.json` — и больше ничего. Из него собирается
и сетка карточек, и кнопки фильтра по регионам, сразу на трёх языках.

```json
{
  "flag": "tr", "photo": "istanbul",
  "query": "Istanbul Hagia Sophia Bosphorus", "region": "middle-east",
  "country": { "tk": "Türkiýe", "ru": "Турция",  "en": "Türkiye" },
  "city":    { "tk": "Stambul", "ru": "Стамбул", "en": "Istanbul" }
}
```

| Поле | Что это |
|---|---|
| `flag` | имя файла в `assets/flags/` без расширения — обычно код страны |
| `photo` | имя файла в `assets/photos/` без расширения |
| `query` | что искать на Unsplash, если фотографию будет качать скрипт |
| `region` | к какой кнопке фильтра относится: `europe`, `asia`, `middle-east`, `cis` |
| `country`, `city` | названия на трёх языках |

**Чтобы добавить страну:**

1. Скопируйте любую запись в `data/countries.json` и поменяйте значения.
2. Положите флаг в `assets/flags/`. Брать здесь:
   [flag-icons](https://github.com/lipis/flag-icons), папка `flags/4x3`,
   лицензия MIT — можно использовать в коммерческих проектах.
3. Положите фотографию города в `assets/photos/` — или дайте скрипту
   скачать её, см. раздел про фотографии ниже.
4. Запустите `node scripts/sync-layout.js`.

**Чтобы убрать** — удалите запись целиком и запустите тот же скрипт.

⚠️ Фотографии может не быть: карточка тогда соберётся без неё, на тёмной
плашке с фирменным пунктиром. Вёрстка при этом не ломается.

⚠️ Названия кнопок фильтра лежат там же, в разделе `regions`, а подписи
вроде «Не нашли свою страну в списке?» — в разделе `labels`.

## 5а. Фотографии городов

**Папка:** `assets/photos/`, по одному файлу на страну.
**Требования:** WebP, 480×320, не тяжелее 22 КБ. Их выдерживает скрипт.
**Откуда:** сейчас — [Викисклад](https://commons.wikimedia.org/), список файлов
и авторов лежит в `data/photos.json`.

Пересобрать нынешний набор:

```
python3 scripts/photos.py --commons
```

Если снимки свои или скачаны руками — назовите файлы так же, как в поле
`photo`, и скормите папку скрипту:

```
python3 scripts/photos.py --from ~/Downloads/goroda
```

Скрипт обрежет по центру, приведёт все снимки к одному виду (одинаковые
поправки цвета и контраста на весь набор — иначе двенадцать разных
фотографий рассыпаются), ужмёт до нужного веса и перепишет
`assets/photos/CREDITS.md`. После него — `node scripts/sync-layout.js`.

### Про лицензии — читайте, это не формальность

⚠️ Одиннадцать из двенадцати снимков под лицензиями **CC-BY** и **CC-BY-SA**.
Они разрешают коммерческое использование, но требуют называть автора.
Поэтому:

- в `data/photos.json` у каждого снимка заполнены автор, лицензия и ссылка
  на страницу описания;
- те же данные открыты посетителям на странице `suratlar.html`,
  ссылка на неё — в подвале;
- `node scripts/preflight.js` не даст опубликовать сайт, если у какого-то
  снимка автор или ссылка пустые.

⚠️ **CC-BY-SA** требует ещё одного: обрезанный и сжатый снимок — это
производная работа, и она распространяется под той же лицензией. Строка
об этом стоит у каждого такого снимка на трёх языках. Убирать нельзя.

⚠️ Берите снимки только там, где лицензия разрешает коммерческое
использование: Викисклад (кроме файлов с пометками NC и ND), Unsplash,
Pexels. Картинка из поиска Google — чужая собственность, за неё присылают
счета.

## 7. Добавить вопрос в «частые вопросы»

**Файл:** `index.html` (строка ~694) и страницы услуг
**Искать:** `<details class="faq__item">`

Один вопрос выглядит так:

```html
<details class="faq__item">
  <summary class="faq__q">
    <h3>Вопрос?</h3>
    <svg class="faq__icon" viewBox="0 0 20 20" aria-hidden="true">
      <path d="M3 10h14"/><path class="faq__icon-v" d="M10 3v14"/>
    </svg>
  </summary>
  <div class="faq__a">
    <p>Ответ.</p>
  </div>
</details>
```

Чтобы добавить вопрос — скопируйте весь этот кусок целиком (от `<details>`
до `</details>`), вставьте следом и замените текст вопроса и ответа.
Кусок с `<svg>` не трогайте, это плюсик справа.

Чтобы убрать вопрос — удалите весь кусок целиком.

**После правки:**
```
node scripts/sync-layout.js
```
Вопросы попадают в разметку для поисковиков — команда её обновит.
Разметка берёт ровно те вопросы, что есть на странице: выдумать ничего нельзя.

## 8. Поменять пункт меню или ссылки в подвале

Меню и подвал лежат **по одному разу** и раскладываются по всем страницам.

| Что | Файл | Строка |
|---|---|---|
| Меню, туркменское | `partials/header.html` | ~28 |
| Меню, русское | `partials/header.ru.html` | ~28 |
| Меню, английское | `partials/header.en.html` | ~28 |
| Подвал | `partials/footer.html` и `.ru`, `.en` | ~17 |

Один пункт меню:

```html
<li class="site-nav__item">
  <a class="site-nav__link" data-nav-key="wizalar" href="wizalar.html">Wizalar</a>
</li>
```

`data-nav-key` — метка пункта, по ней подсвечивается текущий раздел.
Если добавляете новый пункт — придумайте ему свою метку.

**После правки обязательно:**
```
node scripts/sync-layout.js
```
Без этой команды правка останется только в `partials/` и на сайте не появится.

## 9. Логотипы: какой файл для чего

Все лежат в папке `assets/`. На сайте подключены не все — часть нужна
для других мест.

| Файл | Где используется |
|---|---|
| `logo-header.svg` | шапка сайта |
| `logo-header-light.svg` | шапка на главной, пока она прозрачная поверх тёмного первого экрана |
| `logo-horizontal.svg` | запасная горизонтальная версия: печать, документы |
| `logo-horizontal-light.svg` | подвал, на тёмном фоне |
| `favicon.svg` | иконка во вкладке браузера |
| `favicon-light.svg` | то же, когда у браузера тёмная тема |
| `og-image.svg` → `og-image.png` | картинка-превью, когда ссылку кидают в мессенджер |
| `logo-mark.svg` | знак без надписи; из него сделаны иконки для телефона |
| **`logo-mark-copper.svg`** | **медная версия знака — для аватара в соцсетях.** На сайте не используется: берите этот файл для Instagram, Telegram и других профилей, где нужна круглая или квадратная аватарка. |
| `logo-vertical.svg`, `logo-vertical-light.svg` | вертикальная компоновка: печать, вывеска, презентации |
| `logo-mono-black.svg` | одноцветный, для документов и факсов |
| `apple-touch-icon.png`, `icon-192.png`, `icon-512.png` | иконки для экрана «Домой» на телефоне |

### Если заменили логотипы

1. Положите новые файлы в `assets/` **с теми же именами**.
2. Проверьте пропорции: они записаны в самих файлах, в атрибуте `viewBox`.
   Если они изменились, поправьте `width` и `height` у картинки логотипа
   в `partials/header.html` и `partials/footer.html` (и в версиях `.ru`, `.en`)
   — иначе логотип обрежется. Сейчас там записано: шапка 690×140,
   подвал 622×224.
3. Перерисуйте картинки: `apple-touch-icon.png`, `icon-192.png`,
   `icon-512.png` и `og-image.png` делаются из новых svg.
4. Запустите `node scripts/sync-layout.js`, затем `node scripts/preflight.js`.

⚠️ **Не запускайте `node scripts/optimize-svg.js` на готовых логотипах
от дизайнера.** Они уже сжаты. Скрипт нужен только если вы принесли
необработанный svg из редактора.

## 10. Два шрифта: какой где

| Шрифт | Что им набрано | Файлы |
|---|---|---|
| **Inter** | весь текст: абзацы, кнопки, меню, подписи | `assets/fonts/inter-*.woff2` |
| **Unbounded** | только заголовки h1 и h2 | `assets/fonts/unbounded-*.woff2` |

Оба лежат внутри проекта, из интернета не подгружаются. У каждого три
файла — латиница, расширенная латиница, кириллица: браузер скачивает
только ту часть, буквами из которой набрана страница.

Если добавите текст с буквами, которых на сайте раньше не было
(например, начнёте писать на четвёртом языке), пересоберите шрифты:

```
python3 scripts/subset-fonts.py
```

⚠️ Заголовочный шрифт знает только те буквы, что уже стоят в заголовках,
плюс полные алфавиты трёх языков. Обычная правка текста пересборки
не требует.

## 11. Движение: как оживить новый блок

Отдельных скриптов на секции нет — всё делает `js/motion.js` по атрибутам
в разметке:

| Атрибут | Что происходит |
|---|---|
| `data-reveal` | блок поднимается снизу и проявляется, когда доходит до экрана |
| `data-reveal="fade"` | только проявляется, без подъёма |
| `data-reveal-group` | ставится на список: карточки появляются друг за другом |
| `data-reveal="dash"` | сам блок стоит, «пробегает» пунктирный разделитель над ним |

Длительности и плавность — в `css/tokens.css`, раздел «Движение».
Там три длительности и две кривые, других значений на сайте быть не должно.

⚠️ Если в системе у посетителя включено «уменьшить движение», всё стоит
на месте — это обязательное требование доступности, не убирайте его.

## Если сломалось

1. Возьмите последнюю копию: `node scripts/backup.js --list`
2. Скопируйте файлы из папки `backups/дата-время/` обратно в корень проекта.
3. Запустите `node scripts/preflight.js` — убедитесь, что всё в порядке.

Ничего страшнее этого случиться не может.
