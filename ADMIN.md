# Панель для специалиста — что нужно сделать владельцу

Панель уже написана и проверена. Осталось завести ей хранилище и учётную
запись. Это делается один раз, примерно за двадцать минут.

Пока эти шаги не сделаны, панель на сайте не работает — но и сайту она не
мешает: публичные страницы её не загружают вообще.

---

## Коротко, что вы получите

Адрес `visawaygroup.com/admin/`. Вход по почте, паролю и коду из
приложения на телефоне. Внутри — все 72 пары «виза + страна», редактор
с русскими подписями и предпросмотр на трёх языках.

---

## Шаг 1. Завести хранилище

1. Откройте [vercel.com](https://vercel.com) и войдите.
2. Выберите проект **visawaygroup**.
3. Вкладка **Storage** → **Create Database** → **KV** (Upstash Redis).
4. Имя любое, например `visaway-admin`. Регион — ближайший к Ашхабаду
   из предложенных (обычно это Франкфурт, `eu-central-1`).
5. Нажмите **Connect** и подключите базу к проекту visawaygroup,
   к окружениям **Production**, **Preview** и **Development**.

После этого Vercel сам добавит в проект переменные `KV_REST_API_URL` и
`KV_REST_API_TOKEN`. Копировать их руками не нужно.

**Почему KV, а не Postgres.** Данных мало и они несвязные: 72 документа,
два-три пользователя, несколько сессий. Ни одного запроса, ради которого
нужен SQL. Зато сессии и блокировка входа живут по таймеру — в KV срок
жизни ключа встроен, а в SQL пришлось бы держать поле с датой и вручную
подчищать протухшее. И обращение идёт по обычному HTTPS, без драйвера и
без пула соединений: пул к Postgres из бессерверных функций — известная
морока, соединения кончаются.

**Про бесплатный тариф.** Наши данные — около 400 КБ: 72 записи
примерно по 4 КБ плюс мелочь. Обращений — сколько раз специалист
откроет страницу, то есть десятки в день, не тысячи. Это далеко внутри
бесплатного тарифа Upstash по любому из его ограничений. Актуальные
цифры смотрите на странице тарифов Upstash: они меняются, и повторять
их здесь означало бы однажды соврать. Если когда-нибудь упрётесь —
превышение у Upstash не ломает базу, а переводит на платный тариф,
и вы это увидите в письме от Vercel.

## Шаг 2. Завести себе учётную запись

На своём компьютере, в папке сайта:

```
node scripts/admin-init.js user ваша-почта@пример.ру owner
```

Скрипт спросит пароль дважды. Требования: не короче 12 знаков, и он
проверяется по базе утёкших паролей — если ваш пароль где-то когда-то
утёк, скрипт откажет и попросит другой.

Потом он покажет ключ для приложения-аутентификатора — строку из букв
и цифр. **Она показывается один раз.**

Возьмите телефон, откройте Google Authenticator (или Authy, 1Password,
Aegis — любое), выберите «Добавить вручную» и введите этот ключ.
В приложении появится шестизначный код, который меняется каждые
30 секунд. Он и будет вторым фактором при входе.

Без приложения вход не работает. Это не настройка, это устройство
панели: отключить нельзя.

Так же заводится специалист, только с ролью `editor`:

```
node scripts/admin-init.js user почта-специалиста@пример.ру editor
```

Ему точно так же покажут ключ — передайте его лично, не письмом.

---

## Шаг 3. Перенести требования в базу

```
node scripts/admin-init.js import
```

Возьмёт всё из `data/requirements.json` и положит в базу. Проверить:

```
node scripts/admin-init.js check
```

Должно показать 72 записи и заведённых пользователей.

---

## Шаг 4. Посмотреть у себя, до выкладки

```
node scripts/admin-dev.js
```

Откроется `http://localhost:8787/admin/` — панель со всеми данными,
ровно такая же, какой будет на сайте. Здесь можно спокойно потыкать
всё подряд: данные лежат в отдельном файле у вас на компьютере и на
сайт не попадают.

---

## Шаг 5. Выложить

```
git push
```

Vercel соберёт сайт и поднимет панель. **За первой выкладкой стоит
проследить:** в проекте появился `package.json`, которого раньше не
было. Vercel должен просто установить зависимости и оставить сайт
статическим — публичные страницы как лежали готовыми файлами, так и
лежат. Если что-то пойдёт не так, откат — одна команда:
`git revert` последнего коммита.

После выкладки откройте `visawaygroup.com/admin/` и войдите.

---

## Шаг 6. Ссылка пересборки — без неё не работает «Опубликовать»

Кнопка «Опубликовать» в панели просит Vercel собрать сайт заново.
Чтобы он послушался, нужна ссылка пересборки:

1. Vercel → проект **visawaygroup** → **Settings** → **Git** →
   раздел **Deploy Hooks**.
2. **Create Hook**: имя любое, например `panel`, ветка `main`. Create.
3. Скопируйте появившийся адрес.
4. **Settings** → **Environment Variables**, добавьте переменную
   `VERCEL_DEPLOY_HOOK` со скопированным адресом, для всех окружений.

Этот адрес — ключ: кто его знает, тот может запускать пересборку.
Не выкладывайте его никуда.

Без этой переменной панель работает, но при нажатии «Опубликовать»
честно скажет, что публикация не настроена.

## Что изменилось в сборке сайта

Раньше страницы собирались у вас на компьютере и ложились в репозиторий
готовыми. Теперь их собирает сам Vercel: в `vercel.json` появилось
`buildCommand`, а собирает `scripts/build-vercel.js`.

Иначе было нельзя. Требования теперь лежат в базе, а не в файле, —
значит, собирать надо там, где база доступна в момент выкладки. Иначе
кнопка «Опубликовать» не могла бы ничего изменить.

Порядок сборки: выгрузить требования из базы → собрать страницы →
прогнать `preflight`. Если `preflight` не пропускает, сборка
останавливается с ошибкой, и **Vercel не заменяет сайт** — прежняя
версия продолжает работать.

**За первой выкладкой после этой правки стоит проследить.** До неё
Vercel выкладывал файлы как есть, теперь у него появился шаг сборки.
Если что-то пойдёт не так — откат одной командой: `git revert`.

## Шаг 7. Письма — не обязательно

Письма приходят о двух вещах: когда в панель пять раз подряд не смогли
войти и когда специалист что-то опубликовал. Чтобы они приходили:

1. Заведите бесплатный ключ на [resend.com](https://resend.com).
2. В Vercel: проект → **Settings** → **Environment Variables**,
   добавьте две переменные:
   - `RESEND_API_KEY` — ключ с resend.com
   - `ADMIN_OWNER_EMAIL` — ваша почта

Без них панель работает как обычно, только письмо не уходит, а запись
об этом остаётся в журнале Vercel.

## Что дальше

Вторым заходом делаются: история правок с откатом к любой прошлой
версии, письма о каждой публикации и кнопка «Опубликовать», которая
сама пересобирает сайт. Пока публикация идёт как раньше:

```
node scripts/admin-init.js export
node scripts/build.js
node scripts/preflight.js
git push
```

---

## Если что-то не работает

**Панель открывается, но пишет «Что-то пошло не так».** Скорее всего, не
подключено хранилище. Vercel → Storage → база должна быть Connected
к проекту.

**Не приходит код в приложении.** Проверьте время на телефоне: код
считается от часов. Если телефон отстал на минуту, коды не сойдутся.
В настройках телефона включите автоматическое время.

**Забыли пароль.** Заведите себя заново другой почтой с ролью `owner`,
войдите и удалите старую запись командой `check` — она покажет, что есть
в базе. Сброс пароля из самой панели появится вторым заходом.

**Вход закрыт на 15 минут.** Это защита от подбора: пять неудач подряд.
Просто подождите.
